## Goal
Let the player order a trained creature from home, house it in a paddock, assign it to work, and collect capped passive production into a finite bin. Implement the Tuftle worker producer (slow fiber/berry cycles) as the representative producer; Craghopper/Glade Stag/Snarlfox roles come in a later feature.
## Ground rules (the codebase already follows these)
- Simulation stays Phaser-independent: gameplay logic lives in `src/simulation/**` over the serializable `GameState` (`src/simulation/state.ts`); scenes only render state and turn input into validated commands; tunables live in `src/content/**` and `src/config/**` with no scattered magic numbers.
- Determinism: no `Math.random()` or wall-clock reads in simulation — use the injected seeded RNG and injected clock; coins, bin counts, and cycle/remainder timers are fixed-point integers; new authoritative gameplay state (roster assignments, bins, producer remainders) must be included in the canonical determinism hash, and recomputable/metadata values excluded. Confirm the determinism hash test still passes.
- Commands revalidate atomically at resolution: ordering, assigning, releasing, and collecting validate all inputs, coins, roster capacity, and housing/output capacity before mutating anything; a failed transaction consumes nothing and never deletes or duplicates a creature or resource.
- Gating uses the UNLOCK-POINTS system only: register `farm-counter`, `small-pen`, and `barn` in `src/simulation/unlockPoints.ts` `UNLOCK_COSTS` (spend `state.unlockPoints`, push id into `state.unlockedItemIds`). Do NOT gate any new content by tile area — ignore `AREA_TIERS` / `highestAreaTierEver` / `minEnvironmentArea` and never reference tile thresholds in UI copy. Housing physically operates only inside a valid `workYard` (paddock) environment — keep that environment-kind fit as a functional operation gate, not a pacing gate. Use the predicate system in `src/simulation/unlocks.ts` only for functional prerequisites where noted below.
- Persistence: every new `GameState` field (bins, producer timers, assignment state) needs a migration in `src/persistence/migrations.ts` with a bumped `saveVersion` plus a migration unit test; a failed/invalid migration must never overwrite current, last-known-good, or the raw pre-migration backup.
- Content validation: every new placeable and producer definition must declare `efficiencyAxes` (`src/content/efficiency.ts` / `validation.ts`); the validation test must fail the build if any are missing.
## Scope
- Placeables: add Farm Counter, Small Pen (contributes 1 housing slot), and Barn (contributes 3 housing slots), each registered in `unlockPoints.ts`. Pen and Barn operate only in a valid `workYard` paddock.
- Housing capacity: for one paddock, `buildingHousingSlots` is the sum of valid housing facilities in it, and capacity is `min(buildingHousingSlots, floor(paddockArea / 8))`, where `paddockArea` is that built environment's actual usable cell count (functional geometry, not a progression tier). Invalid housing moves its assigned creatures to a safe `rest` state and pauses their work; reassign when capacity returns; animals and stored output are never deleted.
- Farm orders: wire the existing `FARM_ORDER_CONTRACTS`, `FARM_ORDER_COSTS`, and `FARM_ORDER_RATING` in `src/content/economy.ts` into a working Farm Counter command and UI. An order requires the species in `firstTamedSpeciesIds` (the `firstTamedSpecies` predicate), `highestRatingEver >= FARM_ORDER_RATING`, an atomic coin debit at `FARM_ORDER_COSTS`, and both roster capacity and valid housing capacity. Release/resale is confirmed and refunds no more than 25% of the coin cost. Sighting a species is never sufficient.
- Assignment states: each owned creature is `follow`, `work`, or `rest` — never follow and work simultaneously. At most 3 active followers; roster cap is `MAX_CREATURE_ROSTER` from `src/content/creatures.ts`. A fourth follow/mount assignment is rejected with a choose-replacement prompt, never a silent dismissal.
- Producer (Tuftle): add a typed producer definition with `cycleMs`, optional `inputPerCycle`, `outputPerCycle`, its required facility + collection bin, and `efficiencyAxes`. A stationed Tuftle runs slow fiber/berry cycles into a finite Pen/Barn bin. Full storage stops work and blocked cycles are lost, never banked for a later burst. Passive output should be roughly 20–30% of same-tier active collection. Completed output increments `state.workerResourcesProduced`.
- Offline settlement: worker producers use the cycle/remainder rule from "Capped offline work": `completedCycles = floor(availableMs / cycleMs)`, `actualCycles = min(completedCycles, inputAllowedCycles, freeStorageAllowedCycles)`, persist only `nextEligibleRemainderMs < cycleMs`, honor the default 8-hour cap (`OFFLINE_CAP_MS`), a backward clock advances nothing, and a formerly-full bin never bursts. Extend `src/simulation/offline.ts` and follow its existing grower-settlement pattern — do not write a parallel settlement path.
